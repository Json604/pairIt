PairIt - AudioRelay for Windows — 1.1.0 preview

Extract the complete ZIP, then open PairIt.exe inside it.
Keep the DLLs, runtime, Fonts and licenses folders together. The .NET runtime
is included. This x64 preview is unsigned and has not run on Windows
in our build environment. Its API minimum is Windows 10 build 19041; use a
supported Windows installation. ARM64 is not offered.

Open PairIt from its notification-area icon. Choose Pair a phone to show a
private QR code, then scan it in the phone app. Settings contains the audio
source and update controls. Pair a phone enables sharing from the selected
source; actual capture begins only when a phone requests audio.
Keep phones on a reachable local network and allow TCP 5002 on that trusted
private network if Windows asks. Clear the clipboard after pairing.
Nearby discovery uses multicast UDP 5353 on the local network. If blocked,
QR pairing still works. Discovery never broadcasts the private pairing token.

Choose Phone or Computer under Audio output to switch while
keeping phone connections ready. Computer speakers stops sending phone audio;
Windows keeps its existing local output. Switching back resumes active phones,
while paused phones stay paused. Stop sharing ends the connections separately.

Please check on Windows:
1. The tray icon, settings and pairing windows, keyboard controls and your display scaling.
2. Audio reaches your phone/headphones; Stop, reconnect and closing/reopening
   the tray window work. Ordinary listening continues when Windows locks.
3. Up to four phones share one source; a held phone still occupies a slot.
4. With updated phone apps, switching to phone audio holds relay. Only the
   last active listener may ask a compatible Windows media player to pause.
5. After a phone call or other phone audio interrupts listening, resume from
   PairIt or its notification. Network-loss reconnection is handled separately.
6. Phone Pause/output changes do not arm automatic return. Locking Windows
   suppresses player control until unlock; unlock does not rearm an old hold.
7. A long listening session remains stable, including phone screen lock.

Windows player control is best effort through GSMTC, not universal multipoint.
Unsupported apps can keep playing on their existing local output. Pause those
apps yourself if needed. PairIt does not reroute to speakers, change system
volume/default devices or send automatic Play. A pending Windows Pause command
can delay a new listener; retry Start audio after that player responds.

Windows has no Mac-driver video compensation, and different headphones are
not guaranteed to be acoustically synchronized. Phone microphone controls are
not offered. Read README.md for full source/output, identity and USB limits.

Report Windows version, display scale, phone/headphone types, exact steps and
visible errors. Never include private pairing codes, identity files or audio.
Build and synthetic TLS checks passed; physical Windows/audio checks remain.

Update notices: PairIt checks for new releases while in use. When available,
Check for updates is available in Settings. Download, quit PairIt, then replace
the complete extracted folder. Your pairing identity remains in your profile.
